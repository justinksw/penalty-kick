## 2. 向き・構図

- **v1 は縦のみ。** 横画面は作らない。回転を促すダイアログも出さない。
- 視点: キッカーの背面からゴールを見る（Flor 提案。一番読める PK の構図）。キーパーは遠く小さく、キッカーは近く大きく。ボールはキッカーの手前（足元に埋め込まない）。ゴールラインまでの地は平坦な図の背景（天候の空ではない）。キーパーはロック前も結果も、足がライン上（ゴールマウスの中）に見えること。ラインは細い白（チョーク）で明示する。
- 芝は平坦な緑を一色（必要ならごく弱いトーン差まで）。芝刈り縞や手前へ沈む写真的なグラデは置かない。場が場に見えるためのごく薄い線（ゴールライン、小さめのペナルティエリアの線、スポットの円）は図解としてよい。
- ゴールは画面上部の **表示**。実寸 7.32:2.44（約 3:1）を画面いっぱいにすると、320 幅では口が低すぎてセルが読めない。だからヒット対象は下のパッドに置く。
- ゴール絵は本物の 3:1 よりわずかに高くして口が読めるようにしてよい（目安 約 2.4–2.6:1）。正方形にはしない。画面上の実尺は不要（Flor: 比例の感じで足りる）。
- **ゴールの 3×3 が主役。** マスは等しく、罫は強い。選中は塗り ＋ 太い枠 ＋ 読み上げ行 `右上 · コース`。区のラベルは親指帯に置く。390 で「まんなか」がマスに収まらず混むので、ゴール絵自体にはラベルを書かない。
- ゴール幅は左右に余白を残して中央寄せ（390 ならおおよそ 300×118）。デスクトップでもコントロール列は中央、最大約 430。ピッチ自体は画面いっぱいでよい（中央に白いアプリカードを浮かべない）。
- セーフエリア: ノッチ／Dynamic Island とホームインジケータを避ける（`env(safe-area-inset-*)`）。`蹴る` がホームバーに沈まないこと。

## 3. 操作（片手・ロックする流れ）

実機の iPhone では、上のゴールは親指が届かない。3×3 のヒット対象をゴール絵に置かない。

1. **区をタップ**（パッド）。選中のまま残る。ゴール側の同じマスがハイライトされる（鏡）。
2. **コース または パワー**をタップして力度を決める。初回の初期値は **コース**。以後は前回使った方。区だけ選んで力度に触らなくても、初期／前回値で蹴れる。
3. **蹴る**。区が選ばれるまで無効（押せない・見た目も無効）。

2〜3 タップ。誤射を避ける。v1 にタイミングバーは置かない。ドラッグして蹴る操作もしない。

**コース** ＝ Flor の **巧射**（枠に入りやすい。読まれると止まりやすい）。  
**パワー** ＝ Flor の **大力**（止められにくい。外れやすい）。  
文言を短くしただけで、機制は変えていない。

力度の任意一言（パッドとボタンのあいだ、12px・secondary）:

| 選中 | 一言 |
|------|------|
| コース | 枠に入りやすい |
| パワー | 止められにくい |

キーパーは **ロック前に飛び方向を見せない**。中央、ゴールライン上。確認のあと、ボールの飛行と同時に左右またはその場へ動く（ゴールラインからスタートして見えること）。

飛行中は区・力度・蹴る・難易度をロック。

**もう一回**: 同じ難易度のまま狙い画面へ戻る。選中区はクリア。力度は前回値を残す。ページは再読込しない。

## 4. ワイヤー（390）

### 4.1 狙い（準備）

ゴール側の 3×3 は等しいマスと強い罫（表示のみ）。区ラベルは下のパッドだけ。

```
┌──────────────────────────────┐
│ PK                     ふつう │  ← 難易度は稀なので上部で可
│ 3 / 7                   連続 2│
│ 入った数／蹴った数            │
│                              │
│         ╔════════════╗       │
│         ║  ·   ·  ▓  ║       │  ゴールは表示のみ
│         ║  ·   ·   · ║  守   │  右上が鏡のハイライト
│         ║  ·   ·   · ║       │  キーパーはまだ中央
│         ╚════════════╝       │
│               人  ●          │  キッカー（背面）とボール
│                              │
│ 右上 · コース                │  いまの選択（テキストでも示す）
│ ┌─────┐ ┌─────┐ ┌─────┐     │
│ │ 左上 │ │  上  │ │ 右上 │    │  親指帯
│ └─────┘ └─────┘ └─────┘     │  セル ≥48px
│ │  左  │ │まんなか│ │  右  │    │
│ │ 左下 │ │  下  │ │ 右下 │    │
│ [   コース   ] [   パワー   ] │  ≥44px
│ 枠に入りやすい               │
│ [            蹴る           ] │  ≥44px・区選択後に有効
└──────────────────────────────┘
```

### 4.2 結果（例: ゴール！）

ピッチの結末（ボールとキーパー）は隠さない。濃い全面オーバーレイやネット模様でゴールを覆わない。結果の語は 44–52px / 700。図解向けの濃い輪郭を付け、ゴールの下のピッチ上で読む（写真的なグローは付けない）。

```
│ PK                     ふつう │  HUD は残す・数字は更新
│ 4 / 8                   連続 3│
│         ╔════════════╗       │
│         ║  ·   ·  ●  ║       │  ボールが右上（見える）
│         ║  キ  ·   · ║       │  キーパーは逆へ（この例では左）
│         ╚════════════╝       │
│          ゴール！             │  一番大きい声・輪郭あり
│      [     もう一回     ]    │  親指帯に置く
└──────────────────────────────┘
```

セーブ／枠外も同じ位置・同じ大きさの語。枠外のときだけ、語の下に一行（例: 上に外れた）。色は語を助けるだけで、語の代わりにしない。

結果画面ではキッカーを外す（「ゴール！」と重ならないようにする）。ゴール前の結末（選んだマスのボール、逆へ倒れるキーパー）だけ残す。

柱・バーに当たって入ればゴール、外に出れば枠外。v1 に「ポスト」という第三の結果は作らない。アニメで柱をなめてもよい。

### 4.3 難易度の確認

キックとキックのあいだだけ変更可（飛行中は不可。結果画面は「あいだ」なので変更してよい）。

1. HUD のいまの難易度をタップする  
2. 三つ出す（やさしい／ふつう／むずかしい）。各 ≥44px  
3. 同じ値 → 閉じるだけ  
4. 違う値 → 確認:

```
│ 難易度を変えると、             │
│ 得点はリセットされます         │
│ ふつう  →  むずかしい          │
│ [  やめる  ]  [  変える  ]    │
```

文は読点のあとで改行する（「され／ます」で切らない）。シートは下から被せ、ピッチ（ゴール）は薄く残してよい。パッドの上に中途半端に重ならないよう、下側を十分に覆う。

`変える` で得点 0 / 0・連続 0 にして新しい難易度を付け、狙い画面へ。`やめる` は何も変えない。誤タップで消さないための確認であり、長い説明は不要。

## 6. 人物とモーション

人物は汎用のキッカー＋キーパーだけ。単純な CSS / SVG シルエット。顔のパーツ、ユニフォームの徽章、実在の体型模写はしない。ボールは白い円に細いインクの輪郭。商標パターン（有名なパネル配色など）は使わない。

リズム（読みやすさ優先・短い）:

| 段階 | 目安 |
|------|------|
| キックの踏み | 150–200ms |
| 飛行 ＋ キーパーの動き | 同時・450–600ms |
| 結果の語 | その直後 150ms で出す |
| 合計 | おおよそ 0.8–1.0s |

`prefers-reduced-motion: reduce` のときは飛行とダイビングを省略または極短にする。**結果の語は必ず残す。** 色や動きだけで結果を伝えない。

## 8. レスポンシブと片手

- モバイルファースト。基準 **390**。証明幅 **320 / 360 / 390 / 430**。
- **desktop Chrome** と **iPhone WebKit**（Safari と iOS Chrome）。Justin 要件: 日本語 UI は 320–430 で CJK のはみ出しが以前あったので、両方見る。
- 横スクロールなし。3×3 パッドは 320 でも三列が同時に見える（横スクロール依存にしない）。
- タップ: コース／パワー／蹴る／もう一回／難易度／確認ボタン ≥**44px**。3×3 セル ≥**48px**（320–430）。
- 縦が短い端末では、先に縮めるのは中央の景色（キッカーの大きさ）。パッドと `蹴る` は縮まない。
- 430 でもヒット対象は下三分の一に置く。ゴールを大きくしすぎてパッドを押し下げない。
- デスクトップ: 縦構図のまま中央カラム（コントロール最大 ~430）。横レイアウトは作らない。

## 13. Self-critique

C への差し替えを 390 で描いて見て、直したこと:

- **階層:** A の昼空・芝刈り縞・ネット模様・白いポストをやめ、ゴールの 3×3 を紙色の等しいマスと強い罫にした。選中（右上）が図の主役として先に読める。結果画面ではキッカーを外し、「ゴール！」をゴールの下に置いた。全面スクリムは使わず、結末（右上のボール、左へ倒れるキーパー）が見える。
- **字:** 結果の語は 48px / 700 のまま。写真的なぼかし字影をやめて、図解向けの濃い輪郭にした。HUD は静か、パッド 13px、「まんなか」「むずかしい」は従来どおり折らない指定。確認文は読点のあとで改行。
- **色:** トークンを C 用に入れ替えた。文字は不透明な hud-bar の上。選中は塗り `#E2B93A` ＋太い `#1A2218` の枠（初稿は inset だけだとギャラリー縮小で弱かったので、外環を足した）。無効の `蹴る` は面と字を変える（opacity 禁止）。隣り合うゴールマスの色差だけでは約 1.6:1 なので、枠と読み上げ行が必須——両方ある。
- **余白:** 確認シートは下から被せ、ゴールは上に薄く残す。パッドの中段に浮かない。短い縦では景色から縮め、48px セルと `蹴る` は守る。
- **片手 / a11y:** ゴールはヒット対象にしない。選中は色＋枠＋テキスト行。結果はテキスト必須。コントラストは本文・ラベル・ボタンでおおむね 4.5:1 以上。`prefers-reduced-motion` は受入条件のまま。
- **構図:** キーパーはマウス内・ライン上。キッカーは近く大きく、ボールは手前（スポットの円の中）。人物にグローは付けない。ゴール比は約 2.54:1（300×118）。正方形にはしていない。区ラベルはパッド側だけ（390 のマス高約 33px では「まんなか」が混む）。

残るリスク: C は練習用具／作戦盤に寄るので、「試合の臨場感」は薄い。それは選定の結果であり、A に戻す理由にはしない。選中マスは色だけに頼らないこと（枠と `右上 · コース` を実装でも落とさない）。
